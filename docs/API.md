# REST API Plan (Phase 1)

Base path: `/api/v1`. JSON errors use a stable `{ error: { code, message, details? }, requestId }` envelope. List endpoints use bounded cursor or page pagination. Mutations validate with Zod and return explicit status codes.

| Area | Planned endpoints |
|---|---|
| Health | `GET /health` |
| Auth | `POST /auth/register`, `/auth/login`, `/auth/logout`, `/auth/refresh`; `GET /auth/me`; `PATCH /auth/profile` updates the display name; `GET /auth/export` downloads private JSON account records; `PATCH /auth/password` verifies current password and revokes sessions; `POST /auth/verification/resend` and `/auth/verification/confirm`; `POST /auth/password-reset/request` and `/auth/password-reset/confirm` (email actions require SMTP; one-time tokens are hashed and expire). |
| Profile | `GET/PATCH /users/me`, `PATCH /users/me/password`, `DELETE /users/me` |
| Workspaces | CRUD `/workspaces`; membership listing and invitation/removal under `/workspaces/:id/members` |
| Documents | `GET/POST /documents`, `PATCH/DELETE /documents/:id`, `GET /documents/:id/download` (implemented; owner-scoped; PDF, DOCX, UTF-8 TXT; 10 MiB upload cap) |
| Website sources | `GET/POST /sources`, `POST /sources/:id/refresh`, `DELETE /sources/:id` (implemented; public HTML only, 2 MiB cap, bounded redirects, owner-scoped chunks; refresh reuses safe-fetch checks and rolls back failed re-indexing) |
| Notes/folders | `GET/POST /notes`, `PATCH/DELETE /notes/:id`; `GET/POST /folders`, `PATCH/DELETE /folders/:id` (implemented; folder deletion keeps notes and clears their folder assignment) |
| Chat | `GET /chat/conversations`, `GET/PATCH/DELETE /chat/conversations/:id`, `POST /chat/ask` (creates or appends to an optional `conversationId`; PATCH renames a saved conversation; retrieval accepts owned `documentIds`, `websiteSourceIds`, and `noteIds`) |
| Saved items | `GET/POST /saved-items`, `DELETE /saved-items/:id` (implemented; source ownership and excerpt are verified against the cited chunk) |
| Quizzes | `GET /quizzes`, `POST /quizzes/generate`, `GET /quizzes/:id`, `POST /quizzes/:id/attempts` (implemented; Groq required for generation; owner-scoped server scoring) |
| Flashcards | `GET /flashcards`, `POST /flashcards/generate`, `DELETE /flashcards/:id` (implemented; saved owner-scoped decks generated by Groq only from selected or owned source passages) |
| Tasks | `GET/POST /tasks`, `PATCH/DELETE /tasks/:id` (implemented; private owner-scoped task planner) |
| Assignments | `GET/POST /assignments`, `PATCH/DELETE /assignments/:id`, `POST /assignments/:id/submit` (implemented; private instructions and response drafts; submitted state is only recorded in StudyRAG) |
| Notifications | `GET /notifications`, `PATCH /notifications/:id/read` (implemented; creates owner-scoped in-app reminders from incomplete tasks and unsubmitted assignments due within 7 days; refreshed on page open) |

Every private route requires authentication. Every record route checks owner or explicit workspace membership/permission before access. Teacher, employee, and business UI distinctions do not grant cross-user access by themselves. The current auth API exposes `/auth/me`. Document listing accepts `page`, `limit` (max 50), and `q`; upload uses multipart field `file`. `GET /notes` accepts `q`, `POST /notes` creates a note, and `PATCH/DELETE /notes/:id` update or remove one. Note titles are limited to 120 characters, bodies to 10,000 characters, and each note supports up to ten tags. `POST /sources` accepts `{ "url": "https://…" }`; only public HTML pages are fetched, with DNS/IP validation, redirect revalidation, an 8-second timeout, and 2 MiB response cap. Chat accepts optional `websiteSourceIds` and `noteIds`; selected IDs restrict retrieval to those owned documents, websites, and notes. Answers cite source sections, including saved note sections. Chat and quiz/flashcard generation require `GROQ_API_KEY`. `POST /quizzes/generate` accepts optional `documentIds`, `websiteSourceIds`, `difficulty` (`easy`, `medium`, `hard`), and `questionCount` (3–10); source lists left empty include all the user's ready sources. Quiz reads hide correct answers; `POST /quizzes/:id/attempts` submits one option index per question and returns a server-scored result with explanations. Chat passage retrieval uses owner-scoped keyword ranking; generation runs through Groq on the server.
